# Joinery: agent instructions

Shared instructions for every coding agent on this repo (Claude Code, agy, others).
`CLAUDE.md` and `GEMINI.md` import this file; edit conventions here, not there.

## What Joinery is

Internal web app for a custom joinery business with two locations (Cornwall area, Ontario).
Staff manage leads, consultations, designs, schedules, installs, payments and QuickBooks sync.
Specs live in `docs/projects/`. The stack is in `docs/architecture/stack.md`.

## Commands

| Task                         | Command                                                  |
| ---------------------------- | -------------------------------------------------------- |
| Install                      | `npm ci && npm ci --prefix functions`                    |
| Dev server                   | `npm run dev` (Vite on 5173)                             |
| Emulators                    | `npm run emulators` (UI on 4000; project `demo-joinery`) |
| Lint + format check          | `npm run lint` (fix: `npm run lint:fix`)                 |
| Typecheck                    | `npm run typecheck`                                      |
| Unit tests (app + Functions) | `npm test`                                               |
| Security rules tests         | `npm run test:rules` (needs Java 21)                     |
| E2E + accessibility          | `npm run test:e2e`                                       |
| Build + bundle budget        | `npm run build && npm run size`                          |

**Definition of done** for any change: lint, typecheck, `npm test` and build pass; rules tests
pass if `firestore.rules` or `storage.rules` changed; e2e passes if UI changed.

## Layout

```
src/                 React SPA
  routes/            TanStack Router file routes (thin: wire a route to a feature component)
  features/<area>/   Components, hooks and tests for one product area
  lib/               firebase.ts, firestore.ts (live-read adapter), query-client.ts
  stores/            Zustand, UI state only
  routeTree.gen.ts   Generated by the router plugin. Never edit; it is committed.
shared/              Code used by both app and Functions: Zod schemas, config, pure logic
functions/           Cloud Functions v2 (Node 24), bundled with esbuild so shared/ is inlined.
                     Its own package.json and lockfile (not a workspace) so deploys use tested versions
tests/rules/         Firestore and Storage rules tests (emulator)
e2e/                 Playwright + axe
docs/                Docs as code: ADRs, roadmap, backlog, specs, runbooks
```

## Rules that are easy to get wrong

- **Dependencies** (ADR 0002): exact pins only, newest release at least 14 days old (security fixes
  excepted). Generate lockfiles with npm 11 (Node 24); npm 10 `npm install` crashes resolving this tree (`npm ci` works). New install
  scripts are blocked by `allowScripts`: review before approving.
- **ADR first.** Do not add a dependency, Firebase service, or exception to `docs/architecture/stack.md`
  without an accepted ADR in `docs/adr/`. Items tagged ADR in the stack are not installed yet on purpose.
  If a task needs one, draft the ADR (status Proposed) and stop for review.
- **Region** is `northamerica-northeast1`, set once in `shared/config.ts`. Never hardcode another.
- **Security rules:** deny by default. Access is by the `role` custom claim only. Rules cannot hide
  fields, so restricted data goes in separate documents. Every rules change needs a test in `tests/rules/`.
- **Never deploy.** Do not run `firebase deploy`, create Firebase projects, or touch real projects.
  Deploys go through GitHub Actions after alias verification.
- **Data shapes** are Zod schemas in `shared/schemas/`; parse at every boundary (Firestore reads,
  Function inputs, third-party responses).
- **Live reads** use `useLiveDocument` / `useLiveQuery` in `src/lib/firestore.ts`. TanStack Query is
  for mutations and one-shot calls. Zustand is UI state only.
- **Money** is integer cents. **Dates** for install and delivery are calendar dates, not timestamps.
- **No personal data to AI or logs.** Names, phones, emails and addresses never go to Claude calls,
  Sentry, or console logs.
- **Accessibility:** WCAG 2.2 AA. Every interactive element is keyboard-reachable and labelled.
- **Bundle:** initial JS under 250 KB gzip. Lazy-load heavy routes and libraries.
- **Styling:** Tailwind v4 utilities from tokens in `src/styles.css` `@theme`. No raw hex in components.

## Code style

Biome formats and lints (single quotes, no semicolons, 2 spaces, 100 columns). TypeScript strict
with `noUncheckedIndexedAccess` and `exactOptionalPropertyTypes`. Use `@/` for `src/` and `@shared/`
for `shared/`. Keep route files thin; exporting components from route files breaks code splitting.

## Commits and PRs

Conventional Commits (`feat:`, `fix:`, `docs:`, `chore:`…), enforced by commitlint. One concern per
PR. Fill in the PR template, including the ADR line.

## Docs as code

- `docs/ACTIVE_CYCLE.md`: what is being worked on now. Update it when you finish an item.
- `docs/BACKLOG.md`: everything not in the cycle. `docs/ROADMAP.md`: phases and milestones.
- `docs/adr/`: decisions. New ADRs copy `0000-template.md`, take the next number, and are added to the index.
- `docs/projects/`: feature specs. Code that changes spec behaviour updates the spec in the same PR.
