# Joinery: agent instructions

Instructions for every coding agent on this repo (Claude Code and Antigravity CLI read this file;
`CLAUDE.md` imports it). Edit conventions here, not there.

**Standards, in order:** `docs/architecture/lilypad-standard-stack.md` (Lily Pad, every project),
then `docs/architecture/stack.md` (Joinery choices), then accepted ADRs in `docs/adr/`. Where the
Joinery docs differ from the Lily Pad standard, an ADR records the exception. Process is in
`docs/GOVERNANCE.md`.

## What Joinery is

Internal web app for a custom joinery business with two locations (Cornwall area, Ontario).
Staff manage leads, consultations, designs, schedules, installs, payments and QuickBooks sync.
Specs live in `docs/projects/`; roles in `docs/personas/`.

## Commands

| Task                         | Command                                                                   |
| ---------------------------- | ------------------------------------------------------------------------- |
| Install                      | `pnpm install --frozen-lockfile && pnpm --dir functions install --frozen-lockfile` |
| Dev server                   | `pnpm run dev` (Vite on 5173)                                             |
| Emulators                    | `pnpm run emulators` (UI on 4000; project `demo-joinery`)                 |
| Lint + format check          | `pnpm run lint` (fix: `pnpm run lint:fix`)                                |
| Typecheck                    | `pnpm run typecheck`                                                      |
| Unit tests (app + Functions) | `pnpm test`                                                               |
| Security rules tests         | `pnpm run test:rules` (needs Java 21)                                     |
| E2E + accessibility          | `pnpm run test:e2e`                                                       |
| Build + bundle budget        | `pnpm run build && pnpm run size`                                         |

pnpm comes from `packageManager` in `package.json` (Corepack: `corepack enable`).

**Definition of done** for any change: lint, typecheck, `pnpm test` and build pass; rules tests
pass if `firestore.rules` or `storage.rules` changed; e2e passes if UI changed.

## Layout

```
src/                 React SPA
  routes/            TanStack Router file routes (thin: wire a route to a feature component)
  features/<area>/   Components, hooks, schemas and tests for one product area
  lib/               firebase.ts, firestore.ts (live-read adapter), query-client.ts
  stores/            Zustand, UI state only
  routeTree.gen.ts   Generated by the router plugin. Never edit; it is committed.
shared/              Code used by both app and Functions: Zod schemas, config, pure logic (ADR 0002)
functions/           Cloud Functions v2 (Node 24), bundled with esbuild so shared/ is inlined.
                     Its own package.json and pnpm-lock.yaml (not a workspace)
tests/rules/         Firestore and Storage rules tests (emulator)
e2e/                 Playwright + axe
docs/                Docs as code: governance, ADRs, roadmap, backlog, specs, personas, design, runbooks
```

## Guardrails (Lily Pad standard §19)

1. **Tailwind v4 only.** No `tailwind.config.js`, no `@tailwind` directives, no v3 utilities like `bg-opacity-*`.
2. **Zod v4 syntax.** `z.email()`, `z.url()`, unified `error` parameter, `z.enum()`. Not
   `z.string().email()`, `required_error`, or `z.nativeEnum()`.
3. **Never wrap `onSnapshot` in a TanStack Query `queryFn`**, and never prefetch live Firestore in a
   route loader. Use the subscription adapter.
4. **Never mirror Firestore data into Zustand.**
5. **After changing a custom claim, force `getIdToken(true)`.**
6. **Every `onCall` has explicit try/catch and `HttpsError`**; keep intentional codes, translate
   unexpected errors to `internal`, leak no internals. `functions/src/index.ts` (`ping`) is the model.
7. **Secrets go in Secret Manager.** No `.env` or committed secrets; never ask for or use production
   credentials.
8. **No low-value tests** (snapshots, prop-type checks, library internals). Critical tests say in a
   comment what failure they catch.
9. **Magic link:** never take the sign-in email from the redirect URL; handle cross-device; resolve
   Google/magic-link collisions with `linkWithCredential`.
10. **Zod and UI checks are not security boundaries.** Rules and trusted backend checks are.
11. **"Lighthouse CI passed" is not "Core Web Vitals pass."**
12. **Pin and review major bumps** on React, Tailwind, Zod, Biome, and Firebase packages. No `latest`.
13. **Verify the target Firebase alias/project before any deploy or emulator-vs-real operation.**
    Never point local code at prod.
14. **Pin GitHub Actions to full commit SHAs** and keep workflow `permissions` minimal.
15. **No `any`, unsafe casts, or unvalidated external data.** A necessary cast gets a comment saying why.
16. **Don't change rules, IAM, secrets config, or workflows without flagging it for human review.**

## Joinery rules that are easy to get wrong

- **Dependencies** (ADR 0002): exact pins, newest release at least 14 days old. pnpm enforces this
  (`minimumReleaseAge` in `pnpm-workspace.yaml`); security fixes go in `minimumReleaseAgeExclude`
  and ADR 0002. Dependency build scripts are denied by `allowBuilds`; a new one fails the install
  until reviewed.
- **ADR first.** Do not add a dependency, Firebase service, or exception to the standards without an
  accepted ADR. Items tagged ADR in `stack.md` are not installed yet on purpose. If a task needs one,
  draft the ADR (status Proposed) and stop for review.
- **Region** is `northamerica-northeast1`, set once in `shared/config.ts`. Never hardcode another.
- **Security rules:** deny by default. Access is by the `role` custom claim only. Rules cannot hide
  fields, so restricted data goes in separate documents. Every rules change needs allow and deny tests.
- **Never deploy.** Do not run `firebase deploy`, `firebase login`, create Firebase projects, or touch
  real projects. Deploys go through GitHub Actions after alias verification. The Firebase MCP server
  (`.mcp.json`) is for the emulators and staging only.
- **Data shapes** are Zod schemas in `shared/schemas/` (cross-boundary) or
  `src/features/<feature>/schemas` (app-only); parse at every boundary.
- **Live reads** use `useLiveDocument` / `useLiveQuery` in `src/lib/firestore.ts`. TanStack Query is
  for mutations and one-shot calls. Zustand is UI state only.
- **Money** is integer cents. **Dates** for install and delivery are calendar dates, not timestamps.
- **No personal data to AI or logs.** Names, phones, emails and addresses never go to Claude calls,
  Sentry, or logs.
- **Accessibility:** WCAG 2.2 AA. Keyboard-reachable, labelled, visible focus; role-denied fields are
  omitted from the DOM, never hidden with CSS.
- **Bundle:** initial JS under 250 KB gzip. Lazy-load heavy routes and libraries.
- **Styling:** Tailwind v4 utilities from tokens in `src/styles.css` `@theme` (see `docs/design/`).
  No raw hex in components.

## Code style

Biome formats and lints (single quotes, no semicolons, 2 spaces, 100 columns; `.editorconfig` for
editors). TypeScript strict with `noUncheckedIndexedAccess`, `noImplicitOverride` and
`exactOptionalPropertyTypes` (ADR 0002). Use `@/` for `src/` and `@shared/` for `shared/`. Keep route
files thin; exporting components from route files breaks code splitting.

## Commits and PRs

Conventional Commits (`feat:`, `fix:`, `docs:`, `chore:`…), enforced by commitlint. One concern per
PR. Fill in the PR template, including the ADR line. End with a concise diff summary.

## Docs as code

- `docs/ACTIVE_CYCLE.md`: what is being worked on now. Update it when you finish an item.
- `docs/BACKLOG.md`: everything not in the cycle. `docs/ROADMAP.md`: phases and milestones.
- `docs/adr/`: decisions. New ADRs copy `0000-template.md`, take the next number, and are added to the index.
- `docs/projects/`: feature specs. Code that changes spec behaviour updates the spec in the same PR.
